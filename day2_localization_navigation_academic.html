Two meanings of "where am I?"Localisation in a map

Metric (6-DoF) localisation

Map = 3D points (SfM / SLAM). Answer = camera pose \((R, \mathbf{t})\) in map coordinates.
2D–3D matches + PnP.

Topological localisation

Map = graph of places / images. Answer = which node am I at?
Visual place recognition (image retrieval).

ProblemPerspective-n-Point

Given \(n\) map points \(\mathbf{X}_j\), their pixels \(\mathbf{x}_j\), and \(K\), find \(R, \mathbf{t}\):

$$\lambda_j\,\tilde{\mathbf{x}}_j = K\,(R\,\mathbf{X}_j + \mathbf{t})$$
  • unknowns: 6 (3 rotation + 3 translation)
  • each correspondence: 2 equations
  • minimal case: 3 points → P3P (Grunert, 1841)
  • linear DLT needs 6 points (it ignores that \(R\) is a rotation)

You already used it

  • VO tracking (Day 1, notebook 2)
  • COLMAP image registration (notebook 5)
  • ORB-SLAM relocalisation
  • AR on your phone

P3P geometryThree rays, one triangle

Law of cosines on each triangle \((C, \mathbf{X}_i, \mathbf{X}_j)\):

$$\begin{aligned} a^2 &= s_2^2 + s_3^2 - 2 s_2 s_3 \cos\alpha\\ b^2 &= s_1^2 + s_3^2 - 2 s_1 s_3 \cos\beta\\ c^2 &= s_1^2 + s_2^2 - 2 s_1 s_2 \cos\gamma\end{aligned}$$

With \(s_2 = u s_1,\ s_3 = v s_1\): two conics in \((u, v)\) → a quartic in \(v\) → up to 4 solutions.

Depths known → points in both frames → \(R, \mathbf{t}\) by SVD (Kabsch).

AmbiguityUp to four poses fit three points

Fig. 2. 2000 random triangles: usually 2 real solutions, sometimes 4

All candidates reproject X₁–X₃ exactly. A 4th point (or RANSAC voting) picks the right one.

Our 40-line solver matches cv2.solveP3P to 1e-11.

Real dataMany noisy points, many outliers

EPnP (Lepetit 2009) + Levenberg–Marquardt on the reprojection error. More points, less noise → better pose.

RANSAC + P3P, then refine on inliers. 50% wrong matches → 0.04° / 5 mm error. Plain least squares: 154° off.

Step 1 · coarseImage retrieval with a global descriptor

One vector per image; nearest neighbours = same place. VLAD (Jégou 2010):

$$\mathbf{v}_k = \sum_{i:\,\mathrm{NN}(\mathbf{d}_i)=k} (\mathbf{d}_i - \mathbf{c}_k)$$

Concatenate, normalise, compare with a dot product. NetVLAD (Arandjelović 2016) learns it end-to-end. Today: MegaLoc, AnyLoc (DINOv2), ...

This is also visual place recognition, the localisation step of a topological map.

Graph search on the gridDijkstra vs. A*

$$f(n) = g(n) + h(n)$$
\(h = 0\): Dijkstra. \(h\) = straight-line distance (never overestimates) → A*: same optimal path, ~40% of the expansions.

Sampling-based planningPRM · RRT · RRT* with OMPL

Only needs a collision checker is_valid(q), so it works in high dimensions (arms, drones).

  • PRM (Kavraki 1996): sample a roadmap, then graph search. Good for many queries
  • RRT (LaValle 1998): grow a tree towards random samples. Fast, not optimal
  • RRT* (Karaman & Frazzoli 2011): + rewiring → asymptotically optimal
Fig. 9. RRT on the lounge C-space (stops at the first path)

Same start and goal, 1 s eachRoadmap vs. tree vs. optimal tree

RRT* is anytime: give it more time and the path keeps getting shorter. It even beats A* on the 8-connected grid, whose paths zig-zag along grid directions.

OMPL in the wildSame API, a 7-DOF arm

OMPL (Şucan, Moll & Kavraki, 2012) is the planning back-end of MoveIt, and is used in many navigation stacks.

Since v2.0: pip install ompl.

No metric map neededPlanning on a topological map

Nodes = places where we have images (Day 1 keyframes). Edges = "reachable from here".

Plan = Dijkstra → a sequence of subgoal images. Execute it with a local controller that drives towards the next image: visual servoing / a learned image-goal policy (main lecture).

Takeaways

  • Metric localisation = 2D–3D matches + PnP-RANSAC. P3P is minimal and has up to 4 solutions.
  • hloc: retrieval (coarse) → learned local matching → PnP (fine). Works day-to-night.
  • Place recognition alone = localisation in a topological map.
  • Planning depends on the map: A* on grids, RRT*/PRM (OMPL) in continuous C-space, Dijkstra on place graphs.
  • Real stacks = global planner + local controller.
